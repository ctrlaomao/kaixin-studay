# 两次视觉：先窄探册，再逐题挂课时

## Problem Statement

How might we 在第二次逐题批改前，用一次又短又窄的视觉先锁定年级/册/学科，再把人教该册课时闭集交给第二次识图，让返回的 `lessonId` 落在云库里——同时第一次绝不能再跑全量 `questions[]`？

## Recommended Direction

同一 `recognize_job` 两阶段视觉，不是两次全量逐题。

1. **probe（短、窄）**  
   只根据作业图回答：年级、册、学科、两三个知识点俗称。不要 `questions[]`，不要批改。目标是十几秒级、token 很少。

2. **选册**  
   云函数按人教（有新用新）选出这一册，拉出 `lessonId` + 课时名（+ 章名若短）。英语仍不挂课时。年级/册/学科不全或选不出版 → 第二次退回现状（逐题 + 本地 `matchLesson`），不带空表硬挂。

3. **grade（现有逐题）**  
   现有逐题 prompt，末尾追加本册闭集。模型可填 `lessonId`。**不在表里的 id 丢弃**，再可走现有 `matchLesson` 兜底。不确定留空，禁止乱选邻近课时。

执行仍走现有 drain：一次 drain 尽量只跑一个阶段（probe 或 grade），避免 60 秒内串两次视觉。自动配额需允许同一 job **两次**模型调用（与「失败手动再 1 次」分开记账，避免第二次视觉吃掉重试额度）。

## Key Assumptions to Validate

- [ ] probe 能在明显短于逐题的时间内稳定返回年级/册/学科——用同一张已成功的作业图打 probe，看耗时与字段
- [ ] 年级/册猜对率够用：错册则第二次整表错——抽 10 张家庭作业人工看册是否对
- [ ] 闭集校验后挂上的课时人工可接受——抽已挂 `lessonId` 的题，看是否明显张冠李戴
- [ ] 两次 drain（约 2 分钟）家长能接受——看是否还没刷到就放弃

## MVP Scope

- 先做数学（人教一册清单）；其它科可 probe 出学科后同样选册，但验收以数学为主
- `recognize_job` 增加阶段：`probe` → `grading`（或等价字段）
- probe prompt 与逐题 prompt 分离；课时表只出现在第二次
- 非法 `lessonId` 丢弃；英语不自动挂
- probe 失败：单次逐题 + 本地匹配，行为与现在接近

## Not Doing (and Why)

- **两次都全量逐题** — 超时与费用翻倍，第二次没有新信息
- **整科全年级或整库 JSON 进 prompt** — 超体积、模型读不完
- **一次 drain 内串两次视觉** — 60 秒打不满两次 40 秒级请求
- **embedding / 向量检索课时** — 体验版过重
- **挂错也强行选一个邻近课时** — 打星单位是课时，挂错比挂空更差
- **第一次失败仍用空清单做第二次闭集** — 等于逼模型编 id
- **用手动重试那一次额度顶第二次视觉** — 失败重试会失效

## Open Questions

- probe 与 grade 的 `deepseekCalls` / `modelCallLimit` 如何与「失败手动 +1」并存（建议：阶段计数与重试分开）？
- 控制台若仍是 `glm-4v-turbo`，两次视觉是否直接不可用（应先改回 `glm-5v-turbo`）？
- 清单最长多少行（截断章、只留课时名）才不把第二次再次拖超时？
