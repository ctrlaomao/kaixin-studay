# 拍照检查失败后手动重试

## Problem Statement

How might we 让家长在「同一张作业照」识别失败后，用一次明确的手动操作再跑识图，直到能出题——同时自动路径仍绝不重打模型（避免云函数超时后每分钟空烧中台）？

## Recommended Direction

做 **原 job 上的「用户解锁第 2 次模型调用」**，而不是新建任务、换模型，或引导重拍了事。

家长在检查列表失败行点「重试」。云函数（如 `recognizeHomework` `action=retry`）校验本家庭/孩子、任务处于失败或「完成但 0 题」、且已用过 1 次模型额度。通过后把 job 标回 `pending`，把允许次数提到 2（例如 `manualRetry` / 上限字段），**绝不在 drain 里自动清零 `deepseekCalls`**。执行仍走现有定时器 `drainRecognize`（或云函数内部 `runJob`，不让小程序同步等待）。点完约一分钟下拉刷新。额度用尽后文案改为请重拍。

选这条是因为：家庭自用、列表入口已够；同图再识是已确认的成功标准；硬限 1 次是为防自动空烧，人按了才破一次。新建 job 对审计更干净，但列表语义和批次指针更重，体验版不值。中台成功却落库为空时，当前**不存模型原文**，无法「只重解析」；第二次会再打一枪，这是接受的代价。

## Key Assumptions to Validate

- [ ] 第二次调用对「超时 / parse 空 / 中台错」至少有一类能出题——用已失败的同一 `fileIDs` 点一次重试看 `questionCount`
- [ ] 家长能接受「点了还要等约一分钟再刷新」，不会当成按钮坏了——看是否反复连点
- [ ] 确认框 + 上限 2 次足够挡住误触，不必做冷却或权限——观察是否有人打满两次仍空

## MVP Scope

**做：**

- 检查列表：失败（及完成但 0 题，若产品视为可重试）行展示「重试」
- `retry`：同图、同一 `recognize_job`；自动 drain 仍跳过已满额任务
- 每任务模型最多 2 次（首次 drain 1 次 + 手动 1 次）
- 进行中隐藏按钮；用尽后提示重拍，不再提供重试

**不做见下。**

## Not Doing (and Why)

- **自动换 Key / 换 `VISION_MODEL` / 换压缩策略** — 第二次失败更常是超时或解析，不是「换个模型就好」；体验版不扩运维面
- **落 `rawText` 再只 parse** — 有价值但是另一张卡；本次配额是再打 1 次模型
- **批改详情页重试按钮** — 已选检查列表即可；详情继续下拉刷新
- **无限手动重试** — 中台有成本，且会掩盖必须重拍的糊图
- **客户端同步等待识别结果** — 小程序默认约 3 秒掐死云函数，比第一次更差
- **原图新 job + 批次改挂** — 审计更好，列表/去重/当前 job 语义更重，家庭自用不先做
- **失败只引导重拍、不提供同图再识** — 治不了「中台有题、库里是 0」

## Open Questions

- `done` 且 `questionCount === 0` 是否允许重试，还是仅 `status === error` / `parse_failed`？
- 第二次仍撞 60s 超时、中台其实已成功时，要不要接受「再烧一次」还是另开「存原文」卡？
- 重试后批次 `jobStatus` / `jobError` / `questionCount` 的回写是否与首次 drain 完全同一条路径？
